# Evaluation

Every number on this page is generated by `python benchmarks/make_figures.py` from the
committed `results/*.json`, which the `bench-extended` and `atlas-repro` GitHub Actions
workflows produce from public data. How to rerun everything is on [Reproduce](reproduce.md);
the design rationale is [ADR 0006](adr/0006-benchmark-methodology.md).

## Methodology in brief

| Benchmark | Question | Ground truth | Unit / statistics |
|---|---|---|---|
| B1 causal edges | Which process start caused each effect, with GUIDs hidden? | Sysmon `ProcessGuid` lineage (objective) | effect; CIs resample **captures** (cluster bootstrap, 2,000 reps), paired bootstrap for differences; macro F1 over captures beside the micro F1 |
| Calibration | Do edge confidences mean what they say? | same GUID truth | ECE (10 bins), Brier, AUROC; fit on one corpus, test on another |
| B2 story ranking | Does reading stories reach the labelled technique sooner than a flat list? | ATT&CK labels in OTRF metadata | capture; equal event budget for every method; Wilson CIs, exact McNemar |
| B3 anti-forensics | Are log/timestamp tampering files flagged? | file-name labels (10 positives) | file; Wilson CIs |
| B4 scale | Throughput and rule-engine complexity | - | single run, laptop, pre-parsed events |
| B5 live auditd | Does a real kernel capture reconstruct end-to-end? | scripted benign sequence | 7 assertions in CI (consistency, not accuracy) |
| C ATLAS | Do ATLAS's published numbers follow from its release? | authors' released counts and outputs | exact recomputation |

Fairness rules: baselines see the **same fused, de-duplicated events** as REVENANT (B1) and
the **same event budget** (B2). Earlier versions of B1 and B2 did not, and their more
favourable numbers are withdrawn. Corpus-scale runs happen on GitHub Actions runners, where
no endpoint antivirus quarantines captures; on the author's laptop 18 Empire captures were
unreadable and silently shrank the atomic corpus.

## Headline findings

1. **Causal edges (B1).** On OTRF atomic REVENANT reaches F1 0.910 [0.80, 0.98] vs 0.822
   [0.54, 0.96] for PID-nearest; macro F1 0.931 vs 0.737. The ablation attributes the gain to
   the **image-keyed fallback rules** (0.826 without them). APT29 day 1 and day 2, the LSASS
   campaign and Log4Shell are easy: every reasonable method scores about 1.0.
2. **Calibration.** Hand-set confidences were under-confident (ECE 0.23-0.30). Fitted on
   APT29 and tested on atomic, ECE falls to 0.106 (AUROC 0.78); fitted on atomic and tested
   on LSASS, 0.027.
3. **Stories (B2).** Under equal budgets stories are **not** faster than a suspicion-sorted
   flat list (hit@1 0.28 vs 0.36, McNemar p = 0.06).
4. **Anti-forensics (B3).** Recall 0.60 vs 0.30 for a 1102/104 query, precision 0.20 vs 0.12;
   intervals overlap (10 positives).
5. **ATLAS (C).** The paper's 91.06 / 97.29 / 93.76% entity P/R/F1 is exactly the macro
   average of its released per-attack counts. Re-running the authors' `evaluate.py` on their
   released outputs reproduces the event level exactly (F1 0.9988) but gives entity F1 0.913,
   because the script counts entities differently from the spreadsheet.

## B5: live kernel capture (auditd)

The `live-auditd` CI job runs on every push and weekly on `ubuntu-24.04`: auditd records
benign background load plus a scripted stage → fetch (127.0.0.1 only) → archive → delete
sequence on dummy files, and `revenant analyze --kind auditd` must reconstruct it. Latest
results: 63 events, 7/7 chain assertions, the covering story ranked first (coverage 0.86,
HIGH), 25/25 edges consistent with auditd's own pid/ppid fields. Because the parser reads the
same fields, that agreement is a consistency check rather than independent accuracy.
