# Evaluation

Every number on this page is generated by `python benchmarks/make_figures.py` from the
committed `results/*.json`, which the `bench-extended`, `atlas-repro` and `CI` (live-auditd)
GitHub Actions workflows produce from public data; each section names the run it comes from.
How to rerun everything is on [Reproduce](reproduce.md); the design rationale is
[ADR 0006](adr/0006-benchmark-methodology.md).

## Methodology in brief

| Benchmark | Question | Ground truth | Unit / statistics |
|---|---|---|---|
| B1 causal edges | Which process start caused each effect, with GUIDs hidden? | Sysmon `ProcessGuid` lineage (objective; GUIDs hidden as a proxy for GUID-less sources) | effect; CIs resample **captures** (10,000 reps, seed 7); macro F1 beside micro; paired capture-level sign and Wilcoxon tests for every comparison |
| Calibration | Do edge confidences mean what they say, and do they rank edges? | same GUID truth | ECE (10 bins), Brier, AUROC, selective prediction; fit on one corpus, test on another; capture bootstrap |
| B2 story ranking | Does reading stories reach the labelled technique sooner than a flat list? | ATT&CK labels in OTRF metadata | capture; equal event budget for every method; Wilson CIs, exact McNemar |
| B3 anti-forensics | Are log/timestamp tampering files flagged? | file-name labels (10 positives) | file; Wilson CIs, exact McNemar |
| B3b anti-forensics | Are the OTRF captures the dataset authors labelled T1562.002 flagged? | OTRF ATT&CK metadata (17 captures, 6 entries) | capture and entry; Wilson CIs, exact McNemar |
| B4 scale | Throughput and rule-engine complexity | - | GitHub-hosted runner; median and IQR of 5 runs, 3 per scaling point |
| B5 live auditd | Does a real kernel capture reconstruct end-to-end? | scripted benign sequence | 7 assertions in CI; Clopper-Pearson (consistency, not accuracy) |
| C ATLAS | Do ATLAS's published numbers follow from its release, and does its model re-run? | authors' released counts, outputs and `model.h5` | recomputation; `evaluate.py` re-run; TF 2.3 model re-run diffed against the release |
| C2 REVENANT under ATLAS | How does REVENANT score under ATLAS's own harness? | ATLAS malicious-entity labels, authors' `evaluate.py` | attack; bootstrap over the 10 attacks, Wilson on pooled counts, exact sign tests |

Fairness rules: baselines see the **same fused, de-duplicated events** as REVENANT (B1) and
the **same event budget** (B2); the strongest baseline in B1 (PID-then-image-nearest)
implements REVENANT's own fallback idea, so it bounds what the rest of the engine adds.
Corpus-scale runs happen on GitHub Actions runners, where no endpoint antivirus quarantines
captures.
